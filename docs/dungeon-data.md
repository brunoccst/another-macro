# Dungeon data: the `dungeon:` block of a dungeon macro

Every Another Dungeon macro (`macros/dungeon/<macro>.yaml`) carries the dungeon it runs in a
top-level `dungeon:` block at the end of the file. Its steps are all one action,
`{another_dungeon: <macro>}`, which names the macro itself: the shared engine
(`android/app/src/main/java/anothermacro/logic/AnotherDungeon.kt`) reads that macro's `dungeon:`
block and runs it. The flow every dungeon shares (keys, party, walking, battles, chests,
clearing, rewards) is code, written once; a dungeon is its macro file. The app's macro runner
ignores the block (it only reads the keys it knows), so a dungeon macro is still an ordinary
macro: it can be saved as a draft through the phone connector and run with its data at once.

Game knowledge and mapping notes are not kept here or in the block: see
`docs/knowledge-base/` (`learned/dungeons/<dungeon>.md`: found on the phone; `external/`: wiki
facts). Tests: `tests/test_dungeon_data.py`, `tests/test_dungeon_routes.py`.

## The dungeon

| Key | Meaning |
|---|---|
| `name` | the dungeon's name as the Another Dungeon panel lists it |
| `era` | the era tab of the Another Dungeon map (`"???"` for the tab of that name) |
| `area` | a place on the era's map that opens a smaller map holding the dungeon's label |
| `label` | the label's first line when the game wraps the name |
| `requires` | characters the game asks for in the party; the run's stop names a missing one |
| `boss` | the boss's name (the run tells the boss battle by it); `""` = none to tell |
| `key_cost` | keys one run takes (default 1) |
| `area_map_scrolls` | every look at the area map lines the layout up again |
| `camera_lags` | the run doesn't count a still first second of a walk as a late start |
| `maps` | the maps in the order the run meets them (below) |
| `areas` | a hub dungeon's other chest areas, picked by the macro's `area` option: `<area>: {boss, maps}`; an area's keys replace the dungeon's, the rest stay. An `area` value it doesn't list runs the dungeon's own maps |

## A map

Positions are fractions of the screen as the opened area map shows them.

| Key | Meaning |
|---|---|
| `names` | the area names the run matches in the map's title; one entry covers a map and its rare variant |
| `segs` | streets, `[y, x_from, x_to]` |
| `links` | stairs between two streets, `[x, y_from, y_to]` (the run flicks to take them) |
| `chests` | `[x, y]` of each chest (the run opens the "!" bubble that shows close by) |
| `arrival` | `[x, y]` where the party comes in (the run lines the map up from it) |
| `exit` | `[x, y]` where the way on to the next map is |
| `sparkles` / `fish` / `jars` | `[x, y]` of other stops, planned with the chests in one order |
| `path` | generated by `another-macro dungeon-routes --write` (don't edit by hand: change the layout or `walk.yaml` and run it again). One leg per stop: `R 1180` / `L 2950` = hold right/left that many ms from rest (`walk.yaml` turns time into distance), `U` / `D` = flick up/down at the stairs. The run follows it without opening the area map |
| `boss` | `true` = the boss map |
| `enemies` | `false` = the run doesn't clear the map's enemies |
| `steps` | fixed moves for a map without a layout: `bubble` (open the "!" here), `U`/`D` (flick), `L 1000`/`R 1000` (hold), `chest L` (walk until a chest's "!" shows), `boss L` (walk until the boss's question shows), `gate` (a "!" that asks to travel on: Yes), `yes` (Yes to a travel question) |
| `chests_count` | chests on a map without a layout |
| `sparkle_icons` | read the sparkles' spots off the area map |
| `exit_walk` | the way on is walking off the screen's edge at `exit` (no sign) |
| `exit_sign` | only this sign template counts as the exit |
| `area_map_scrolls` | this map's area map scrolls with the party |

## Routes

`another-macro dungeon-routes` prints every map's planned route; `--write` writes each map's
`path:` into its macro file (any indent, so an area's maps too), and `--check` fails when one
is out of date (a test runs it).

## The Phantom Crystal Dimension's worlds

The `phantom-crystal` macro has no `dungeon:` block (it isn't an `another_dungeon` run): its
fixed routes are a top-level `worlds:` list, one entry per world, picked by the world's title
banner, each walked from where the party arrives (no area map there).

| Key | Meaning |
|---|---|
| `title` | the world's own words in its title banner, after "Phantom Crystal Dimension" |
| `route` | the steps from the arrival: `L 1200` / `R 1200` (hold from rest, ms), `U` / `D` (flick), `wait 1.5`, `chest x y` / `cat x y` (tap the "!" nearest that screen spot), `portal x y` (the way on), `stairs x y` (the stairs out of the dimension), `sensationalist` (look for their "!" here: the run stops for the user if it shows), `moves_on` (the world moves on by itself) |
